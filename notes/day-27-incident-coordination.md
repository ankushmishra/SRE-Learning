## Learning goals
- Practice concise incident updates and explicit ownership.
- Keep the current state, actions, and next update visible.

## Fundamentals
Incident coordination separates leading the response, operating the system, and communicating status. On a solo tabletop, simulate those roles in sequence. Updates should distinguish observed facts from hypotheses and state impact, current action, and when the next update is due.

## Practical session
1. Create `~/sre-followon-lab/notes/day27-incident.md` with incident start, impact, status, actions, and next update time.
2. Simulate a localhost health-check failure; do not affect any external service.
3. Write role assignments for incident lead, operations, and communications. As a solo learner, state when you switch roles.
4. Draft a 30-second status update using facts only; label any hypothesis clearly.
5. Add a handoff note with current state, completed actions, open question, and next step.

## Check your understanding
- Which statement is an observation and which is a hypothesis?
- Who owns the next action and the next update?
- What information must a useful handoff preserve?

## Done when
The incident state note and concise update make it clear what is known, happening, and next.
